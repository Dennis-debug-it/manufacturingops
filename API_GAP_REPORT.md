## Summary

**Total gaps found: 14**

| Severity | Count | Notes |
|---|---|---|
| Critical | 0 | All core flows (auth, work orders, clients, invoices, quotations, materials, PM, portal) are fully wired to real endpoints. |
| High | 0 | No important feature is outright broken. |
| Medium | 7 | 3 are **stale** (backend now exists, frontend still shows a "pending backend" placeholder); 4 are the Platform CRM/Announcements expansion (no backend yet). |

**Headline:** there are **no critical or high gaps**. The most impactful items are **3 stale placeholders** (WhatsApp dashboard widget, Inventory PO report, Finance Payables-aging report) whose backends were built in recent phases but whose frontends were never re-wired — these are pure frontend fixes.

## Fix Plan

### Batch 1 — Quick wins (< 1 hour each)
_Wrong paths / wrong methods / missing field mappings._

**None.** No wrong-path, wrong-method, or missing-response-field gaps exist. The only item that is "small correction" flavoured is gap #4 (swap the raw GUID text input for the existing `useTechnicians()` dropdown) — listed under Batch 3 because it's a frontend wiring change, not a path correction.

### Batch 2 — Backend endpoint needed (backend work required)
_These frontends already exist and are stubbed; they need a real controller before the frontend swap._

1. **Platform CRM — Contacts** (gaps #5). New `PlatformCrmContactsController` (`api/platform/crm/contacts`):
   - `GET /` → `[{ id, companyName, contactName, email, phone, role, leadId?, createdAt }]`
   - `POST /` ← `{ companyName, contactName, email, phone, role }`
2. **Platform CRM — Activities** (gap #6). `PlatformCrmActivitiesController` (`api/platform/crm/activities`):
   - `GET /?contactId=&leadId=` → `[{ id, type, subject, notes, occurredAt, actorName }]`
   - `POST /` ← `{ type, subject, notes, occurredAt, contactId?, leadId? }`
3. **Platform CRM — Tasks** (gap #7). `PlatformCrmTasksController` (`api/platform/crm/tasks`):
   - `GET /?status=` → `[{ id, title, dueDate, status, assigneeName, relatedLeadId? }]`
   - `POST /` ← `{ title, dueDate, assigneeUserId?, relatedLeadId? }`
   - `PUT /{id}` ← `{ status | title | dueDate }`
   - _(Entities: `CrmContact`, `CrmActivity`, `CrmTask` — platform-scoped, root-tenant. One migration.)_
4. **Platform Announcements** (gap #8). `PlatformAnnouncementsController` (`api/platform/announcements`):
   - `GET /` → `[{ id, title, body, audience, isPublished, publishedAt, expiresAt }]`
   - `POST /`, `PUT /{id}`, `POST /{id}/publish`
5. **Platform System Health** (gap #9). `PlatformHealthController` (`api/platform/health`):
   - `GET /services` → `[{ name, status, latencyMs, checkedAt }]` (DB, email outbox, storage)
   - `GET /jobs` → `[{ name, lastRunAt, status, nextRunAt }]`
   - _(Can be computed live — no new tables needed; probe DB, `email_outbox_messages` backlog, etc.)_
6. **Platform CRM & Support settings** (gaps #10, #11). Reuse the existing generic module-settings store pattern (`TenantModuleSetting`) but platform-scoped, OR add two small key-value endpoints under `PlatformSettingsController`:
   - `GET/PUT api/platform/settings/module/crm`
   - `GET/PUT api/platform/settings/module/support`

### Batch 3 — Frontend wiring needed (frontend work required)
_UI exists, backend exists — just connect it. These are the highest-value, lowest-cost fixes and should be done first._

1. **Dashboard WhatsApp Alerts widget** (gap #1) → call `GET /api/whatsapp/conversations`, show the latest N with unread counts; replace the dashed placeholder.
2. **Inventory Reports → PO tab** (gap #2) → call `GET /api/purchase-orders`, render a spend-by-supplier / status table (reuse `usePurchaseOrders`).
3. **Finance Reports → Payables Aging tab** (gap #3) → call `GET /api/payables`, bucket by `dueDate` age (Current / 1–30 / 31–60 / 60+) and show outstanding = `amount − amountPaid`.
4. **T&A New Leave technician field** (gap #4) → replace the "Technician GUID" `<input>` with a `<select>` fed by the existing `useTechnicians()` hook.

### Batch 4 — Full feature gaps (both frontend and backend work needed)
_New backend **and** a frontend swap off the stub. (The CRM/Announcements/Health frontends already exist, so "frontend work" here is just swapping the stub hook for a real one.)_

1. **Platform CRM module** — build Batch 2 endpoints #1–#3, then swap `platform/crm/crmStubApi.ts` hooks to real `api.get/post/put` calls and drop the `throw new Error` bodies + "UI stub" toasts in `ContactsPage`/`ActivitiesPage`/`TasksPage`.
2. **Platform Announcements** — build Batch 2 endpoint #4, then wire `AnnouncementsSettingsPage` + the `ShellSettingsPages` Announcements card.
3. **Platform System Health** — build Batch 2 endpoint #5, then wire `HealthSettingsPage` + the `ShellSettingsPages` Health card.
4. **Platform CRM/Support settings** — build Batch 2 endpoint #6, then wire `CrmSettingsPage`/`SupportSettingsPage` save handlers.
5. **Tenant Integrations (API keys + webhooks)** (gap #12) — _deferred by design._ Real API-key issuance + webhook delivery is security-sensitive; current copy already states it is platform-provisioned. Build only if programmatic API access becomes a product requirement.
6. **Portal self-service profile edit** (gap #13) — add `PUT /api/portal/profile` (tenant portal scope) and wire `PortalProfilePage`. Low priority.
